# 彼爱团队 · 官方触达与用户说明产品方案

> 状态：**已落地（P0–P2 首版）**  
> 更新：**2026-11**  
> 关联：[`PRODUCT.md`](./PRODUCT.md) §23（IM/勿扰）、§24（H5 双端）、[`USER-PRODUCT-GUIDE.md`](./USER-PRODUCT-GUIDE.md)（产品说明维护）

---

## 1. 背景与目标

| 项 | 说明 |
|----|------|
| **要解决** | 用户注册后不知道「彼爱能干什么、去哪看规则」；使用中问题与建议缺少固定入口；运营需要克制的全员告知能力 |
| **不解决** | 不做通用客服 IM 产品、不做营销号式促活、不用发现底栏红点催读 |
| **成功标准** | 新用户 1 次看懂能力与反馈路径；官方触达月频可控；长说明有持久页（非仅 30 天 IM） |

**品牌气质：** 温润近人、「被接住地读经」；零 guilt、读经优先（对齐 §2 / §23.7）。


## 3. 用户侧信息架构

### 3.1 通讯录：平台常驻联系人

- **位置：** 发现 → 通讯录 → 好友列表 **最上方固定一行**（非 friendship 表计数成员）
- **关系类型：** `platform_official`（合成注入 API，或前端 merge；**不可删除、不可加好友、不可改备注**）
- **点击：** 官方资料页（发消息 / 产品说明 / 反馈；无「删除好友」）
- **头像：** App 图标 + 可选细标「官方」

### 3.2 会话列表

- 欢迎信 fan-out 后自然出现「彼爱团队」会话（与设置里「帮助与反馈」**同一会话**）
- 未读遵循 §23：底栏「发现」**无角标**；仅在发现内消息列表显示未读
- 会话内灰字：**消息约保留 30 天**；完整说明见 [产品说明](/help/product)

### 3.3 设置入口

| 入口 | 行为 |
|------|------|
| **产品说明** | `/help/product`（已实现：用户向正文） |
| **帮助与反馈** | `openDm(70625146)` → 同一会话 |

安卓发现/设置相关路径在 H5 白名单 `/help`、`/discover` 下，**业务迭代以 Web 发布为主，一般不另发 APK**（§24）。

## 4. 消息触达：欢迎信 + 全员信

### 4.1 两类任务

| 类型 | 触发 | 受众 | 频率 |
|------|------|------|------|
| **welcome** | 账号首次就绪（注册/合并完成） | 单用户 | 每用户每模板版本 1 次（幂等） |
| **broadcast** | 超管后台 | 全员或子集（如近 N 天活跃） | 建议 **≤2 次/月**（可配置硬闸） |

### 4.2 发送管道（产品契约）

```text
触发 / 管理后台
    → OutreachJob（草稿｜待发送｜发送中｜完成）
    → Worker fan-out（限速）
    → 每用户：建/取 direct_thread + insert message（sender=官方）
    → platform_outreach_delivery 幂等
    → 可选推送（尊总开关 + 会话免打扰 + 读经勿扰）
```

**权限：** 仅平台超管（与活动运营同级）；全员信二次确认 + 预估人数 + 审计日志。

### 4.3 消息形态

| kind | 用途 |
|------|------|
| **notice**（推荐） | 标题 + 正文 + 0～3 个 CTA（链到 `/help/product` 等） |
| **chat** | 短纯文本全员信 |

**持久内容不进 IM 唯一副本：** 手册类正文以 `/help/product` 为准；IM 仅摘要 + 链。

### 4.4 欢迎信定稿文案（短版 · notice 正文）

**标题：** 欢迎使用彼爱

**正文：**

> 你好，欢迎来彼爱读经 App。这里有小爱帮你解释经文，可以和同路人共读，浏览属灵书籍，探索圣经里有意思的主题，也能分享你的观点。更多用法请看产品说明；有问题随时在这里回复我们。

**CTA：**

| 文案 | 链接 |
|------|------|
| 产品说明 | `/help/product` |

（可选第二按钮「开始读经」→ 首页或 `/reader`，P1。）

### 4.5 与活动运营分工

| | 彼爱团队 IM | 活动运营 |
|--|-------------|----------|
| 长度 | 短 | 可多日课 |
| 落点 | 发现私信 | 首页推荐 / 活动页 |
| 场景 | 致歉、版本说明、轻征集 | 专题营、节期活动 |
| 纪律 | 同一件事不双通道轰炸 | 受众过滤，非成员零打扰 |

## 6. 反馈与建议收集（分期）

| 阶段 | 能力 |
|------|------|
| **P0** | 私信彼爱团队 + 产品说明 |
| **P1** | 设置内短表单（类型/场景/描述）→ 工单后台；可选自动回执 notice |
| **P2** | 活动「提问箱」控件征集（见 `CAMPAIGN-OPS.md`） |

收集原则：结构化优先、IM 补充；禁止 guilt 式「还不反馈吗」推送。

## 7. 管理后台（产品菜单）

```text
管理后台
└── 用户触达（超管）
    ├── 欢迎模板 welcome_v*（版本化，升版仅新用户）
    ├── 全员信（草稿 → 预览 → 受众 → 发送进度）
    └──（P1）反馈工单列表
```

与 **活动运营** 分菜单，不混入口。

## 8. 合规与体验硬约束（验收必过）

- [ ] 发现底栏永无未读角标；圣经 Tab 无消息红点/横幅  
- [ ] 官方行不可删、不可加好友；`70625146` 搜索不可申请  
- [ ] 欢迎信每用户每模板 1 次；全员信有月频与审计  
- [ ] 客户端不能以普通用户身份代发官方消息  
- [ ] 文案无排行榜、无「你落后了」类 guilt  
- [ ] 产品说明可长期访问；IM 内 30 天规则诚实告知  
- [ ] IM **唯一 Web 实现**（§24）；安卓不发版即可承载 H5+API 变更
